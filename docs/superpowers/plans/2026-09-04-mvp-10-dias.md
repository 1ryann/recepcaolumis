# MVP de 10 dias — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Não iniciar implementação neste turno; autorização atual é para planejamento técnico.

**Goal:** Transformar o protótipo aprovado em operação integrada de recepção, locações e agenda, respeitando o escopo congelado.

**Architecture:** Monólito modular ASP.NET Core com API autenticada, EF Core/SQL Server e React existente. Mesmo domínio público para SPA/API, armazenamento privado de fotos, tarefas persistentes/idempotentes e SignalR para atualização do painel. Separar modelo financeiro, locação, ocorrência, visita e acesso.

**Tech Stack:** React/TypeScript/Vite e CSS existentes; ASP.NET Core Identity, EF Core SQL Server, SignalR, testes xUnit com SQL Server isolado e testes de fluxo no navegador. Versões fixadas antes da execução. SDK local observado: 9.0.315; projeto net9.0 e EF 9.0.17. Atualização para .NET 10 LTS autorizada pelo usuário: alvo net10.0, pacotes Microsoft 10.0.11 e SDK 10.0.400. A validação desta atualização será registrada em docs/operations/dotnet-10-upgrade.md.

**Spec:** `docs/superpowers/specs/2026-09-04-mvp-congelado.md`

## Modelo e limites técnicos propostos

- `ApplicationUser` liga Identity ao profissional quando aplicável. Policies separadas para administração de usuários/integrações, gestão operacional e recursos próprios.
- `Professional`, `Tenant`, `Room`, `Lease`, `RecurrenceRule`, `ReservationOccurrence`, `ReservationRequest`, `Charge`, `Visit`, `VisitTransition`, `AccessEvent`, `AuditEntry`, `PrivateFile`, `BuildingSchedule`, `RoomBlock`, `PrivacySettings`.
- Ocorrências materializam uma janela finita configurada tecnicamente, renovada por tarefa. Chave única de recorrência + início original evita duplicação. Exceções canceladas/reagendadas são preservadas e nunca recriadas pelo gerador.
- Conflitos consultam ocorrências, exceções, bloqueios e regras recorrentes; duas recorrências sem término são comparadas por interseção de vigência/dias/horários, sem enumerar infinito.
- Intervalos técnicos sem sobreposição: `existing.Start < requested.End && requested.Start < existing.End`. Armazenar instantes e fuso explicitamente, usando relógio injetável; confirmar fuso do prédio antes de configurar produção.
- `decimal` para dinheiro, duração em minutos e snapshot da tarifa. Não criar arredondamentos de duração ou política comercial.
- `rowversion` evita edição perdida, mas não basta para inserções sobrepostas. Todas as mutações de agenda usam transação e bloqueios SQL ordenados por sala/profissional, incluindo geração, aprovação, expediente e cancelamento. Validar novamente sob o bloqueio; repetir aprovação não cria segunda reserva/cobrança.
- Mudança de visita, verificação de visitas abertas e encerramento da locação participam da mesma coordenação transacional. Auditoria de negócio gravada com a mutação; sinais publicados depois do commit.
- Jobs retomam após reinício, persistem progresso e não usam timers do navegador como fonte de verdade. Alertas precisam atualizar também pela passagem do tempo, sem depender de clique.
- Fotos fora do webroot, identificadores aleatórios, validação real do arquivo e entrega autorizada. Limpeza de captura e sessão do totem entre visitantes; nenhum dado pessoal persistido no navegador.
- Totem recebe projeção mínima e capacidade de criar chegada; não possui credencial administrativa. Identificação técnica do dispositivo e limites por dispositivo/IP definidos na etapa de infraestrutura, sem ampliar permissões.

4. Formulário de interesse de locação e fallback sem câmera existem no protótipo mas não foram aprovados como regras do MVP: apresentar antes de manter como operação real ou remover visualmente.
